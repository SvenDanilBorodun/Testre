# SPEC C — Appendix 2: the 2.41.0 tower kit, piece by piece, in the native app

Belongs to `SPEC-C-native-app.md` (hard requirement: every piece of `VERIFICATION.md` §6 C1 is carried
over with its tests). Every symbol below was located in the tree on 2026-11-25 (`grep`, CONFIRMED that
it exists where stated). "Unchanged on the runtime" means: the code is not edited; it runs in the robot
tier on the compatibility runtime (Appendix 1) and its existing tests keep running against the same file.

**Rule for the coder:** no piece is re-implemented. A piece is (U) run unchanged, (S) started from its
existing file by a thin native subclass or caller, or (M) moved with `git mv` at the removal package
C7-06. A third copy of a twin module is a defect.

## What the wrist camera (owner decision, role `gripper`) does to the kit

- Recording: C5-01 gives `v1_studio` the second camera role. The tower camera path (T1–T4) is untouched:
  the wrist camera is an ordinary 640 × 480 `_CaptureWorker` on camera id 0.
- The tower guard's arm model, the clip-on calibration target and the claw's reach are **not** changed
  by this spec. Open point O5 (model, mount, cable route) may change `V1_LINK_BOXES`, `arm_cells` or the
  contract; each of those is an ask-first safety change (CLAUDE.md "When to ask the user") and is not
  pre-approved. C5-01 therefore carries the external gate `O5-geometry`: until the owner states that
  the mounted camera stays inside box 5 of `V1_LINK_BOXES` (or approves new boxes), the V1 profile's
  `camera_roles` gain `gripper` only behind the station setting `wrist_camera = false` (default).
